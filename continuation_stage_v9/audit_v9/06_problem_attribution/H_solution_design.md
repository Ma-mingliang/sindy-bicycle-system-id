# H: 解决方案设计

## 执行摘要

V12 根因实验揭示了一个悖论：V12 的 bug 修复（顺序段、扩展课程、RK4、收缩性）产生**更准确的单步和短期预测**，但导致 **H>=50 时灾难性的存活失败**。V9 基线尽管使用有 bug 的 shuffle DataLoader 训练，但在所有 horizon 上保持 100% 存活率——因为其较大的每步误差恰好保持在物理限制内。

---

## Tier 1: 保守方案（最小风险）

### 变更 1: 存活感知损失

**文件**: `neural_ode_v12.py`, 训练循环内 `loss_multi` 之后

添加物理限制惩罚：在训练 rollout 中，预测状态违反物理限制时施加二次惩罚。

```python
loss_survival = sum(relu(|s_check| - limit_norm)^2) / rollout_steps
lambda_survival = 0.1
```

**预期**: Surv@500 从 0% → 40-60%

### 变更 2: 课程上限 H=30

**文件**: `neural_ode_v12.py` V12Config

```python
rollout_curriculum = '1,5,10,20,30'  # 从 '1,5,10,20,50,100' 改为
max_segment_len = 30                  # 从 100 改为
```

**预期**: 消除常数预测崩溃。H=50 NMAE 略升但存活率大幅改善。

### 变更 3: 课程回归检测

在自适应课程调度器中添加回归检测：当进入更高级别后误差增加 50% 时回退。

**预期**: 防止级别过冲。

**Tier 1 目标**: H=50 NMAE < 0.40, H=500 < 0.50, Surv@500 > 50%

---

## Tier 2: 稳健方案（中等变更）

### 变更 4: 多 horizon 采样

每个 batch 从 [1, base_rollout] 中随机采样 rollout 长度（70% 基础级别，30% 随机更短）。

**预期**: NMAE@500 改善 5-10%

### 变更 5: 增强收缩性正则化

```python
lambda_contractive = 0.15  # 从 0.05 增加
contractive_warmup_epochs = 10  # 从 20 减少
contractive_ramp_epochs = 30   # 从 50 减少
```

**预期**: NMAE@500 改善 3-5%

### 变更 6: 推理时状态裁剪

在 predict() 中每步裁剪到物理限制的 95%。

**预期**: Surv@500 从 0% → 80%

### 变更 7: 早停

基于验证 H=1 误差的早停（patience=50）。

**Tier 2 目标**: H=50 NMAE < 0.30, H=500 < 0.45, Surv@500 > 80%

---

## Tier 3: 激进方案（重大变更）

### 变更 8: 自适应积分步长

学习 `dt_ratio ∈ [0.13, 1.0]`，在高曲率区域自动减小步长。

### 变更 9: 多尺度架构

分离快动力学（delta, delta_dot, theta_dot）和慢动力学（e_y, e_psi, v, theta）为不同网络头。

### 变更 10: 模型集成

训练 N=3 个不同种子的模型，平均预测。提供不确定性估计。

### 变更 11: 存活门控课程

课程仅在存活率 > 80% 时升级。

**Tier 3 目标**: H=50 NMAE < 0.20, H=500 < 0.35, Surv@500 > 90%

## 实施优先级

```
Tier 1（从此开始）:
  变更 2（课程上限）→ 变更 1（存活损失）→ 变更 3（回归保护）

Tier 2（Tier 1 验证后）:
  变更 6（裁剪）→ 变更 5（收缩性）→ 变更 4（多 horizon）

Tier 3（Tier 2 验证后）:
  变更 8+9（自适应步长+多尺度）→ 变更 10（集成）
```

**建议**: 从 Tier 1 变更 1+2（存活损失 + 课程上限 H=30）开始。这两个变更以最小代码改动和低风险解决两个最有影响力的问题。
