## 2. Root Cause Analysis

### 2.1 Why 0.064 != 0.066

Same evaluation code path, different training configurations:

- 0.064: 5 NN models, 3 DAgger rounds
- 0.066: 7 NN models, 5 DAgger rounds

Both use: phi-only endpoint error, Mode C style, unseeded, no LR scheduler. The difference is purely from training configuration, and since both are unseeded, the results also vary across runs.

**Verdict**: Same metric, same mode, different training. Neither is reproducible.

### 2.2 Why 0.064/0.066 != 0.252

These measure fundamentally different things:

| Dimension | 0.064/0.066 | 0.252 |
|-----------|-------------|-------|
| Metric | phi-only endpoint error | full-trajectory MAE (4 states) |
| Evaluation mode | Mode C style | Mode B (fixed action) |
| Training | No LR scheduler | CosineAnnealingLR scheduler |
| Seeds | Unseeded | 5 fixed seeds (42-46) |
| Unit | rad | mixed (rad + rad/s) |

The 0.252 includes errors from delta, phi_dot, and delta_dot channels which are not captured by the phi-only metric. Additionally, the training pipelines differ (scheduler vs no scheduler), meaning the underlying models are different.

**Verdict**: Incomparable. Different metrics, different modes, different trained models.

## 3. Final Decision

### 3.1 Which result is authoritative?

**0.252 is the authoritative result for the following reasons:**

1. **More rigorous metric**: Full-trajectory MAE across all 4 state channels is a more comprehensive measure of model quality than phi-only endpoint error.

2. **Reproducible**: Uses fixed random seeds (42-46), making the result deterministic.

3. **Saved to file**: Results are persisted in `full_evaluation_v2.json` with full per-seed, per-horizon, per-model, per-mode breakdown.

4. **Proper evaluation mode**: Mode B (fixed action open-loop) is the correct mode for evaluating world model prediction quality without feedback corruption.

5. **Modern codebase**: Generated by the v2 evaluation pipeline which fixed the Mode B/C bug in the old eval_modes.py.

### 3.2 What are 0.064/0.066?

They are historical results from an earlier evaluation pipeline that:
- Used a less comprehensive metric (phi-only endpoint error)
- Were not reproducible (unseeded)
- Were not saved to persistent files
- Used a different training pipeline (no LR scheduler)

They served as useful benchmarks during development but should not be cited as current results.

## 4. Additional Finding: Old Mode B/C Bug

The old `evaluate/run_ensemble_evaluation.py` produced `ensemble_evaluation_results.json` where Mode B and Mode C are identical for all entries. This was confirmed by:
- Code analysis: old `run_mode_b()` and `run_mode_c()` produce identical action sequences
- Data analysis: zero MAE difference between Mode B and Mode C in the JSON file

This bug was fixed in `eval_modes_v2.py` by using a pre-generated reference trajectory for Mode B.
